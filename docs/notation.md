# 符号与计量约定

同一物理量在理论、JSON 输入和测量报告中保持可换算的单位。局部章节若使用不同符号，应在首次出现时定义。JSON 字段名建议带单位；跨模块接口见 [Models contracts](../models/contracts.md)。

## 资源与执行

| 符号 | 含义 | 单位与边界 |
| --- | --- | --- |
| $F$ | 浮点工作量；乘加计数约定必须明确 | FLOP；不是 FLOP/s |
| $D_r$ | 穿过存储边界 r 的读写流量 | byte；逻辑容量不能代替物理流量 |
| $C_e$ | 指定链路/路径的通信量 | byte；不能把集群总量除单链路带宽 |
| $M(t)$ | 时刻 t 的驻留/工作区容量 | byte；峰值与平均分别统计 |
| $P_{\max},B_{r,\max},\beta_{e,\max}$ | 对应资源服务能力的上界 | FLOP/s 或 byte/s；用于条件资源下界 |
| $P_{\rm eff},B_{\rm eff}$ | 校准的有效速率 | 相同单位；用于预测，不自动形成严格下界 |
| $T,L$ | 执行时间与其条件下界 | s；明确换算为 ms 的边界 |
| $S$ | 依赖路径时间下界 | s；不是全部 kernel duration 之和 |
| $I=F/D$ | 指定边界的算术强度 | FLOP/byte |
| $b,\ell$ | 活跃序列数与上下文长度 | 注明全局/每 rank，以及长度分布 |
| $K$ | 一个生成周期最终提交的 token 数 | 不计被拒绝草稿、padding 或重复产出 |

物理内存用 byte，GiB = $2^{30}$ byte；硬件带宽若用 GB/s，GB = $10^9$ byte。任何混用都先换算。`physical_upper` 表示供模型使用的已声明能力上界，不意味着输入值已经通过硬件核验。

## 服务指标

| 量 | 定义或用途 |
| --- | --- |
| $\lambda$ | 同一边界下的请求到达/接纳率，requests/s；二者不同则分别命名 |
| $\mu$ | 明确工作负载与策略下的服务能力，不能假设动态 batch 恒定 |
| TTFT | 到达/发送到首个有效生成内容的时延，按测量边界定义 |
| TPOT | 首 token 后的平均输出间隔，逐请求计算，再统计分位数 |
| ITL / chunk gap | token 或流式 chunk 的间隔；不要互换名称 |
| Throughput | requests/s、output tokens/s 与 total tokens/s 分别计量 |
| Goodput | 单位时间成功且同时满足预定质量/SLO 的请求数 |

完整定义、单 token 输出、reasoning 与多 token chunk 的处理见 [测量协议](benchmark-protocol.md)。分位数不能相加；含相关量的乘积不能随意拆开期望。

## 优化与搜索

| 符号 | 定义 |
| --- | --- |
| $a,x$ | 候选动作与系统配置，含 parent 与任务契约 |
| $J(x)$ | 预先固定方向的目标效用；最大化/最小化不能混淆 |
| $\mathcal F$ | 质量、容量、资源与功能约束下的可行域 |
| $\Delta T=T_0-T_1$ | 时延节省；正数表示该口径改善 |
| $S_T=T_0/T_1$ | 时延加速比；下界之比另外命名 |
| $\Delta_{AB}=T_A+T_B-T_0-T_{AB}$ | 绝对时间节省口径的交互量；正数为协同 |
| $c_{\rm eval},\mathbf c,\mathbf B$ | 实验成本、已用预算向量和预算上限，与通信量 $C_e$ 区分 |
| $\mathcal H_t$ | 到时刻 t 为止已完成且可见的历史；不包含未来结果 |

有风险惩罚或多资源标量费用时，先固定单位和权重；不能直接相加 GPU 秒与 token 数。实验协议中的 `cost_units` 若来自合成示例，只在该示例内有意义。

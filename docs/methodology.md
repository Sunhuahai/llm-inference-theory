# 研究方法与证据边界

研究单位是一条可检验的判断及其证据链：任务与约束 → 机制假设 → 条件预测 → 独立实验 → 适用域与反例。目录和文章数量不能代替理论或实验进展。

## 1. 每篇理论与每个候选至少写清什么

| 项目 | 要回答的问题 |
| --- | --- |
| 研究对象 | 算子、生成周期、请求还是完整服务？ |
| 不变量 | checkpoint、精度、采样语义、资源和质量约束是什么？ |
| 干预 | 哪个计算/访存/通信/状态/依赖量改变？新增什么成本？ |
| 结论种类 | 恒等式、严格界、近似模型还是经验判断？ |
| 适用范围 | 何种 shape、负载、缓存、并行拓扑成立？ |
| 反例 | 什么观测会否定或迫使修正这个判断？ |
| 证据关联 | 哪个版本的代码、输入、原始结果和分析支持结论？ |

先给直觉与最小算例，再介绍推导。复杂公式必须有定义和假设；使用同一符号的局部变体应明确说明。[符号与单位](notation.md)提供共同约定。

## 2. 证据状态与实现状态独立

| 证据状态 | 含义 | 不能据此声称 |
| --- | --- | --- |
| hypothesis | 待验证机制或预测 | 优化已经有效 |
| derived | 在明示假设下完成推导 | 假设适用于所有引擎 |
| literature | 一手来源报告 | 本项目已复现 |
| simulated | 合成输入或仿真输出 | 真实 GPU/真实 Agent 成绩 |
| user_report | 用户提供的经验或结果 | 已取得独立原始测量 |
| measured | 明确环境下有原始测量 | 已通过独立复测或具有普适性 |
| validated | 预定范围内通过独立复核 | 在范围外也成立 |
| inconclusive | 证据不足或相互矛盾 | 等同于成功或确定无效 |

文档设计、可运行代码、测试通过和真实适配是另一组实现状态。一个能运行的仿真器仍只有 simulated 证据；正确性失败的实测也是有效证据，其候选决定应为 rejected。不要把这些状态压成一条自动升级链。

## 3. 理论界与可达性能

当资源服务能力不超过 $P_{\max}$，且完成任务至少需要 $F$ 工作量时，$T\ge F/P_{\max}$ 才是相应条件下的下界。由一次计时反算的有效速率用于预测，不能自动代入后宣称严格下界。多个资源下界取最大值可能很松，未计入的依赖和资源竞争会使实际时间更长。

下界之比不是实测加速比，也一般不是实际加速的上界。若有候选严格时间下界 $L_1>0$ 和实测基线 $T_0$，才能得到 $T_0/T_1\le T_0/L_1$。只有预测值时，应输出预测与不确定性，并保持对错误预测的探索机会。

## 4. 独立性与成本

拟合参数、选择候选和最终评价分别使用明确的数据边界。改完代码后重新执行冻结的 oracle；不能通过调整评分器接受自己的实现。模型版本和事前预测在观察实验结果前保存，避免事后解释冒充预测。

同预算评价同时计算 profiling、校准、编译、候选生成、失败和复测。比较多 Agent 与单 Agent 时记录总消耗及墙钟时间；比较记忆增强方法时排除测试泄漏，并区分冷启动和摊销成本。

正结果与负结果保留相同粒度的证据。只有被验证的可迁移机制可进入后续决策，旧环境中的失败不能无条件永久禁止新环境候选。

## 5. 从模拟走向实测

CPU 测试验证公式、单位、异常输入和控制逻辑。微基准校准局部执行成本；端到端 A/B 检验服务收益；最终留出检验跨负载适用域。各层互相补充，不互相替代。

## 6. 文献与公共维护

只用原论文、作者代码与官方文档支撑外部技术事实，记录版本/日期和原始设置。自定义推导或评价规则标为本仓库设计，不能自动归因于引用论文。论文中的加速数字不跨模型、硬件或负载迁移。

历史归档只读；活跃文档更正应保留旧证据来源。检查 Markdown 相对链接、GitHub 数学与 SVG 预览；不提交密钥、私密输入或内部地址。新代码以关键不变量和有意义的反例验证，避免测试只复述实现。

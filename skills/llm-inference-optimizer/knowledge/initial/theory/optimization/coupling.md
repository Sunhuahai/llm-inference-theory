# 优化耦合：组合收益、顺序依赖和 Pareto 边界

> 日期：2026-11-25。性质：`derived` 代数关系与 `hypothesis` 实验设计。所有数字是合成例；尚无实测交互结论。

两项优化分别有效，联合后可能相互抵消，也可能让一项原本无效的优化变得有价值。原因包括改动覆盖同一成本、资源瓶颈迁移、执行依赖变化和容量改变。Agent 需要保存条件收益，而非只保存独立加速倍数。

## 1. 四组实验定义一个局部交互量

固定任务、负载、资源预算和测量口径，记基线、仅 A、仅 B、A+B 的时间为 $T_0,T_A,T_B,T_{AB}$。以**绝对耗时节省**定义：

$$
\Delta_{AB}=T_A+T_B-T_0-T_{AB}.
$$

因为组合节省减去单项节省之和为：

$$
(T_0-T_{AB})-[(T_0-T_A)+(T_0-T_B)]=\Delta_{AB},
$$

正值表示在这个口径下联合节省超出相加值，负值表示节省少于相加值，零值表示该工作点上相加成立。换成吞吐、相对比例或对数指标后，交互的数值与含义会变，必须重新声明定义。

**合成例：**

| 配置 | 时间 | 相对基线节省 |
| --- | ---: | ---: |
| 基线 | 100 ms | 0 ms |
| 仅 A | 90 ms | 10 ms |
| 仅 B | 94 ms | 6 ms |
| A+B | 87 ms | 13 ms |

此时 $\Delta_{AB}=90+94-100-87=-3$ ms。B 在已有 A 后只节省 $T_A-T_{AB}=3$ ms，而非其独立的 6 ms。可能原因是二者消除了同一段开销，也可能是组合增加了资源压力；四个数字本身不能确定机制。

## 2. 条件加速可以相乘，独立加速通常不行

只要测量可比，恒等式成立：

$$
\frac{T_0}{T_{AB}}=\frac{T_0}{T_A}\frac{T_A}{T_{AB}}
=S_A S_{B\mid A}.
$$

第二项是在 A 已经生效后测得的条件加速。将它替换成 $S_B=T_0/T_B$，一般没有依据。上述例中总加速约为 $1.149$，独立倍数的乘积约为 $1.182$。

还要区分两种“顺序依赖”：同一个最终配置的条件收益会随所选中间基线改变；另外，变换 $B\circ A$ 与 $A\circ B$ 也可能生成不同代码或配置。后者需要保留最终版本、前置条件与实现路径单独比较。四组开关实验能够估计交互，却不能仅凭交互符号证明代码演化的顺序因果。

## 3. 瓶颈切换会制造正交互

**另一个合成例：** 时间模型为 $T=\max(T_C,T_M)$。基线为 $(10,8)$ ms；A 将计算降到 6 ms；B 将访存降到 5 ms：

| 配置 | 时间 |
| --- | ---: |
| 基线 | 10 ms |
| A | 8 ms |
| B | 10 ms |
| A+B | 6 ms |

因此 $\Delta_{AB}=8+10-10-6=2$ ms。B 单独无时间收益，在 A 后却再省 2 ms。这并不需要复杂的“额外协同算法”，仅资源约束切换就足以产生。

相反，两个候选重复消除同一段 host gap 时容易出现负交互。容量也会产生间接交互：某项内存优化释放 batch 空间，另一项计算优化的形状和吞吐收益随之改变。此时应重算容量和服务模型，不能只给原时间表再加一项修正。

## 4. 估计交互必须保留测量协方差

四组实验应在可比的独立重复块中交错进行，控制缓存、预热、温度及背景干扰；跨块随机化顺序。每块计算一个 $\Delta_{AB}^{(r)}$，再分析其分布。若将四项组成向量 $\mathbf t=(T_0,T_A,T_B,T_{AB})$，$\mathbf c=(-1,1,1,-1)$，则：

$$
\operatorname{Var}(\Delta_{AB})=\mathbf c^\top
\operatorname{Cov}(\mathbf t)\mathbf c.
$$

只有能够支持四组估计独立的条件下，才可把协方差项置零。使用重采样时应以独立运行或能保留相关结构的块为单位；同一个 batch 中的请求通常不是独立实验重复。若区间仍跨零，结论应为 `inconclusive`，不能宣布存在协同或抵消。

Agent 反复搜索许多组合会产生选择偏差：搜索期间最好的噪声点不一定复现。最终候选需要未参与选择的独立复测和留出负载；评价规则不能在看到结果后调整。相关协议见[实验平台](https://github.com/Sunhuahai/llm-inference-theory/blob/1b4c5a37763475eb39b31dd083fcad256fc2578e/experiments/README.md)。

## 5. 多目标与 Pareto 边界

先将精度、正确性、资源预算和必要服务门槛作为可行性约束。对可行候选，可同时比较较小的 TTFT、TPOT、资源成本，以及较大的 goodput。候选 x 若所有目标都不差于 y 且至少一项更好，就支配 y；未被支配的候选构成当前已评估集合的 Pareto 前沿。

这个前沿不等于全局最优前沿，也不自动考虑测量不确定性。某候选平均时延更好但 p99 更差时，应保留真实权衡。若要使用加权目标，单位、归一化、权重与约束必须事先给定，不能直接将 ms、tokens/s 与 GPU-hours 相加。

**可证伪预测：** 模型认为 A 解除计算约束后，B 的条件价值上升；那么 A 后的 profile 应显示约束向 B 对应资源移动，且同负载的 B 条件收益应得到独立支持。若仅时间变好而资源变化不符，收益证据与机制证据要分开登记。

Agent 应将候选绑定到 parent/baseline，记录依赖、冲突和负结果；优先研究能区分“重叠收益”与“瓶颈迁移”的少量组合。表示见[优化机制](mechanisms.md)，预测见[性能模型](../../models/README.md)，搜索与记忆见[自主优化](../../optimizer/README.md)。

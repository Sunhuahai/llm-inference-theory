# 性能边界：哪些优化空间存在，哪些边界可达

> 日期：2026-11-25。性质：`derived` 条件性资源分析；算例为合成数据。本文没有已校准的跨硬件性能结论。

性能边界回答“至少需要多少资源时间”，它适合检查一个目标是否可能实现。实际预测还需要回答资源是否能充分利用、各项工作能否重叠，以及执行依赖是否阻止这个边界被达到。这三件事应分别建模。

## 1. 多资源时间下界

对已确定的算法、输入形状和执行图，设计算工作为 $F$，跨存储边界 $r$ 的流量为 $D_r$，链路 $e$ 的通信为 $C_e$。对应能力上界分别为 $P,B_r,\beta_e$，依赖路径的时间下界为 $S$，则：

$$
T\ge L=\max\left\{\frac FP,\max_r\frac{D_r}{B_r},
\max_e\frac{C_e}{\beta_e},S\right\}.
$$

该式是资源需求不能超过资源供给的结果。计算路径不同的算子要按实际计算单元和精度分账；分布式系统需要逐设备、逐瓶颈链路约束，不能把全集群流量除以一条链路的带宽。存储的容量条件另外满足 $M(t)\le M_{\rm available}$，容量不能代替流量。[Roofline](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2008/EECS-2008-134.html)提供其中计算与内存流量的基础视角。

这里的 $P,B_r,\beta_e$ 必须是适用于研究对象的能力上界。由少量微基准估计出的有效速率通常只是预测参数，以它们计算的时间不能自动称为严格下界。

## 2. 从下界到预测，缺少的是什么

常用算子近似为：

$$
\widehat\tau_j=a_j+\max\left(\frac{F_j}{P_{{\rm eff},j}},
\frac{D_j}{B_{{\rm eff},j}}\right).
$$

有效速率与形状、后端、布局和并行执行有关；$a_j$ 表示未由两种资源时间解释的固定项。这个表达式是待校准模型，没有普适误差保证。用同一条实测时间反解一个效率，再预测该条记录本身，只是重现输入，不是验证预测能力。

执行结构同样决定可达性。两个必须串行的算子，其计算/访存下界分别为 $(8,1)$ ms 与 $(1,8)$ ms，则逐算子的时间下界和是 16 ms；将总工作聚合后只得到 $\max(9,9)=9$ ms。两者都可能是合法下界，后者更松。只有真实变换允许改变执行图，才能进一步讨论融合或重叠的收益。

对已知基线实测时间 $T_0$ 与候选严格下界 $L_1$，实际加速满足 $S_{\rm actual}\le T_0/L_1$。两个下界的比 $L_0/L_1$ 不具有这个一般保证。详见[执行与并行](../execution/README.md)。

## 3. Batch 与上下文的瓶颈相图

对等长 Decode，假设权重一步读取量 $w$ 可在 batch 内共享，每序列计算量为 $f(\ell)$、状态流量为 $k(\ell)$，并忽略其他项：

$$
L_D(b,\ell)=\max\left(\frac{bf(\ell)}P,
\frac{w+bk(\ell)}B\right).
$$

每序列每步提交一个 token 时，$X\le b/L_D$。定义两个不同边界：

$$
b_{WK}=\frac{w}{k(\ell)},\qquad
b_{CB}=\frac{Pw}{Bf(\ell)-Pk(\ell)}.
$$

$b_{WK}$ 仅表示权重流量与状态流量相等；$b_{CB}$ 表示计算与访存下界相等，而且只在分母为正时存在。不能把“KV 比权重读得多”直接等同于“系统实际受 KV 限制”。

**合成相图算例。** 以 $q=\ell/1000$ 表示上下文长度，假设研究区间内每序列计算时间近似固定，并设置：

$$
T_C=0.2b\ {\rm ms},\quad T_M=4+0.02bq\ {\rm ms},
\quad bq\le128.
$$

最后一项是人为给定的容量可行域，不是任何设备规格。于是 $b_{CB}=20/(1-0.1q)$，仅在 $q<10$ 时存在。

| $q$ | 计算/访存相交的 batch | 容量允许的最大整数 batch | 在这个模型中能否到达相交点 |
| ---: | ---: | ---: | --- |
| 1 | 22.22 | 128 | 可以越过 |
| 4 | 33.33 | 32 | 容量先阻止扩 batch |
| 8 | 100 | 16 | 容量先阻止扩 batch |
| 12 | 无有限正交点 | 10 | 仅扩 batch 无法进入计算主导区 |

这解释了为什么最优 batch 不能只由峰值算力/带宽比给出。状态容量和延迟可行域可能先截断性能曲线。实际长上下文还会增加 $f(\ell)$，MoE 的 $w$ 也可能随 batch 变化，均需替换本算例的简化函数。

## 4. 边际收益及边界迁移

在理想访存区域，$X_B=Bb/(w+bk)$，因此：

$$
\frac{\partial\log X_B}{\partial\log b}=\frac{w}{w+bk}.
$$

权重占比下降时，扩 batch 的边际吞吐收益减小。若计算先成为约束，则继续降低内存流量只改善相应资源边界，未必改善总时间。反过来，减少容量占用可以扩大可行 batch，间接重新改变资源瓶颈。

**可证伪预测：** 在声明的形状范围内，模型预言某个 batch 附近发生约束切换；若独立 profile 未出现相应趋势，应检查权重重读、状态流量、并发效率或容量假设。预测不准时要修正模型，不能用理想边界覆盖实测。

Agent 可以用严格不可行条件缩小空间，用边际收益和瓶颈切换预测排序候选，并为靠近相交点的候选保留更多验证预算。实现与校准见[性能模型](../../models/README.md)，诊断见[瓶颈诊断](../diagnosis/README.md)，实验见[实验平台](../../experiments/README.md)，决策见[自主优化](../../optimizer/README.md)。

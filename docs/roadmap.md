# 研究路线：理论、模型与自主优化并行推进

> 2026-11-25。内容完成不等于科学问题已解决；下表分别描述交付与证据要求。

## 1. 当前起点

三条主线已有独立专题与共同评价设计。CPU 解析模型、已有场景预测器及离线搜索回放可执行；所有新示例为合成数据。尚无完整 GPU 优化器、真实 Agent 搜索对照或跨环境实测结论。[内容地图](content-map.md)列出具体文件与能力边界。

## 2. 用共同里程碑推进

| 里程碑 | 理论问题 | 模型工作 | Agent 工作 | 验收所需证据 |
| --- | --- | --- | --- | --- |
| M0：形式与接口 | 成本、诊断、耦合、预算决策 | 资源/DAG 契约与解析参考 | 候选、独立评价、搜索回放 | 文档推导、CPU 边界测试与可复现示例；本次已提供 |
| M1：一个真实工作点 | 哪个观测能区分瓶颈？ | 对一个真实热点校准 | 接入一个 Coding Agent 和固定 evaluator | 环境/负载 manifest、干净基线、独立 oracle、原始 profile |
| M2：预测干预 | 改变资源量后瓶颈如何迁移？ | 预测未用于拟合的候选与形状 | 选择实现/补测/停止 | 预登记预测、A/B、留出误差及失败解释 |
| M3：同预算搜索 | 理论是否提高搜索效率？ | 收益排序与不确定性 | 普通 Agent、显式理论、搜索消融 | 相同权限/预算、多个独立运行、成本曲线与独立复测 |
| M4：组合与迁移 | 什么条件下经验和组合可复用？ | 交互、分布外与再校准 | 多层优化、经验记忆 | A/B/AB 交互、零校准/少量校准分开报告、跨环境留出 |

M1–M3 可以围绕同一个小案例迭代，理论无需预先覆盖所有架构。实验中的反例反向决定下一篇理论应研究什么。

## 3. 近期实施顺序

**先建立真实评价层。** 冻结参考实现、正确性和性能测量；接入资源计费、失败记录和独立复测。可复现实验环境未建立前，不把更多候选生成视为进展。

**再接入一条有限优化链。** 选一个热点、一个候选机制和一个留出场景。把 Agent 输出转换为明确 patch 或配置，再由控制器执行。现有 CPU 回放只验证控制逻辑，不能替代编译与 GPU 的真实适配。

**随后做最小消融。** 普通 Agent 与理论引导 Agent 使用同等工具和预算；额外 profiling、模型校准、检索以及复测成本计入。只有增量效果可复现，才增加分支搜索、持久记忆和多 Agent 编排。

## 4. 各方向的完成定义

- 理论：有假设、推导、反例与能被实验否定的判断，不能以新增章节数验收。
- 模型：能解释留出候选的变化；只复现基线不能证明预测能力。
- 搜索：最终性能与找到它的资源成本一起报告；单次最好成绩不能证明策略优势。
- 迁移：明确哪些代码/参数/经验直接复用，哪些重新校准；不隐藏适配成本。

真实 GPU 运行需使用已确定的计算资源和实验任务。当前仓库保留未填写的环境与 SLO，见 [实验模板](../experiments/templates/README.md)，不猜测设备配置或业务阈值。

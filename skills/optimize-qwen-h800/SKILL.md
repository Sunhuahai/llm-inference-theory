# Qwen H800 单项优化执行助手

把用户指定的一张任务卡变成一个可回滚的小实验。完成当前阶段的检查后再继续下一阶段。每轮只加载这份 skill、选中卡片、相关源码和需要的参考页。

## 1. 固定输入与执行范围

1. 定位**研究仓库**和**实际推理代码仓库**。二者不是同一个概念；不要在研究仓库伪造一个推理框架。
2. 读取研究仓库的 `AGENTS.md`、`environment.yaml`、`docs/benchmark-protocol.md` 和用户指定卡片。用已有环境、首轮最佳有效配置与运行记录补字段；已有信息不重复询问。
3. 读取 [模型与精度合同](references/model-contract.md)。不把官方配置当成用户当前配置，不把代码存在当成实际走到该路径。
4. T001–T013 已归档，不自动重跑。若收到 R01–R03，选其中明确的**一个阶段**，记录其原 T 编号；不要同时实施整条工作流。用户明确要求重访历史实验时另写新实验计划，保留旧结果。
5. 未指定卡片时，从 `rounds/round-03/README.md` 的触发条件选择一个有实际 profile 支撑的候选。没有证据就先做只读盘点，产出缺失项，不凭标题挑最复杂的改造。
6. 仅在用户指定的环境和授权范围内执行。无 H800 或无实际推理代码入口时，继续完成源码分析、设计、CPU 可验证部分；报告阻塞的 GPU 阶段。不要生成假 benchmark 行。

## 2. 使用固定阶段，不跨检查点

| 阶段 | 执行动作 | 必须产出 | 继续条件 |
|---|---|---|---|
| S0 对齐 | 找到现行卡片、实际环境、当前有效 baseline | 任务 ID、两处仓库路径、baseline ID、未知字段 | 已找到原始信息；仅缺 GPU 时可继续只读部分 |
| S1 判定 | 核对源码 SHA、函数、实际 shape/dtype、已内建功能与瓶颈 | 一条假设、一个变量、一个退出条件、源码证据 | 卡片前置条件成立，存在独立新增点 |
| S2 原型 | 在实施仓库隔离分支中只实现最小代码边界，保留旧路径 | 小 diff、默认关闭的实验开关、回滚命令 | 未改模型/精度/采样/输出/预算；原路径可恢复 |
| S3 正确性 | 运行卡片要求的局部对照与相关状态生命周期检查 | 原始输出/误差、边界用例、实际 dtype/math 审计 | 预先约定的正确性合同全部通过 |
| S4 性能 | 保持其他条件相同，交错 baseline/candidate 至少三组 | 原始结果、机制指标、端到端指标、实际资源 | 没有隐藏变量变化、漏计失败或输出长度变化 |
| S5 交付 | 依据证据填写状态与回滚结论 | [交付模板](references/handoff.md) 的完整字段 | 原始证据可定位；成功与负结果都保留 |

S0/S1 的只读检查不等于要求重跑 Week 1。复用已有证据，只补与本次改造有关的缺项。完成一个阶段后输出：`阶段 / 已观察到的事实 / 检查结果 / 下一步`；失败时输出准确缺口和可继续的工作。

## 3. 先写计划，再动代码

从 [experiment-plan.json](assets/experiment-plan.json) 复制一份到实施任务的记录目录。把 `unknown` 换成真实值和可追溯证据。`invariants.candidate` 在原型前记录预期保持值，在 benchmark 前用候选进程的实际读回结果覆盖；不要只复制后宣称已核对。

填写 `single_variable` 时只保留一个条目，例如“路由 GEMM 与现有 top-10 的执行边界”。不能填“统一优化全部内核”。实现 commit 允许变化，但 `engine_base_sha` 指两组共同基点；候选补丁 commit 单独记录。

运行随 skill 附带的结构检查器；把下列路径替换成实际绝对路径，不要照抄占位文本：

```bash
python3 /absolute/research/skills/optimize-qwen-h800/scripts/validate_plan.py   /absolute/run/experiment-plan.json --phase prototype --research-root /absolute/research
```

benchmark 前把 `--phase prototype` 改为 `--phase benchmark`。退出码 2 表示有待补项或合同冲突；默认按类别合并缺项，需逐字段明细时加 `--verbose`。脚本只核对**所填记录的结构和一致性**，不会验证证据真实性、源码数值语义或 GPU 正确性；返回 0 不等于优化已通过。

## 4. 用判断表决定下一步

| 观察 | 动作 | 状态 |
|---|---|---|
| 实际 baseline 已覆盖卡片新增机制 | 记录调用路径和证据，不重复实现 | baseline-covered |
| 找不到卡片函数 | 先用 `rg` 搜函数/类名并查实际版本；记录对应入口，找不到则停止修改 | unsupported 或 blocked |
| 版本、shape、后端、业务条件不满足 | 写明具体条件和最小补充工作；保留可完成的只读产物 | conditional / blocked |
| 代码要求改变 dtype、scale、TF32、采样、输出或卡数 | 停止该实现分支，回到保持合同的设计 | blocked |
| 正确性失败 | 保留失败输入与 diff，修当前变量；无法修复则回滚 | regressed / blocked |
| 只有微基准快，端到端不改善 | 报微基准和端到端两组事实，不升级为服务收益 | inconclusive |
| 收益落在 baseline 波动内 | 保留结果，不扩大扫参掩盖问题 | inconclusive |
| 重复收益超过波动且质量、尾延迟、资源通过 | 附完整证据后记为已验证 | validated |

## 5. 按风险类型读取一页参考

- **所有任务**：读 [模型与精度合同](references/model-contract.md)。特别检查“相同 FP8 标签却重算 scale 或重铸权重”的情况。
- **内核 / 数据布局 / 分布式改造**：读 [执行与验证分支](references/verification-branches.md) 的 A/B/C 部分；使用原 shape、原 reduction 和原输出合同。
- **投机解码 / GDN / QSA / PLE 状态**：读同页 D 部分；先固定小规模正确性，逐一检查拒绝、回滚、取消、slot 复用和 Graph。
- **结果提交**：读 [交付模板](references/handoff.md)，按研究仓库 `templates/result.csv` 与 benchmark 协议填真实结果。

## 6. 约束执行模型的具体行为

- 一次最多修改一个卡片阶段的边界；不顺便升级依赖、换框架、改其他任务的参数或调整业务负载。
- 固定源码网页打不开时，先查实际 checkout 或可用的仓库 API，按锁定 ref 读取；都不可用才记录未独立核验。检索失败不等于功能不存在。
- 用当前代码的 `--help`、类型和调用者核对接口。不从论文标题发明启动开关，不把伪代码写成可直接运行的命令。
- 优先调用已有测试/benchmark 接口；只补能发现此改造真实风险的用例。不为文档创建形式化测试。
- 在数值或状态检查失败时停止性能比较。不要增大容差、删除失败样本、关闭 Graph/MTP/功能后把结果当作原任务成功。
- 可以单独建立诊断用 eager/greedy/小规模实验，但必须标为诊断；生产比较的 Graph、采样、输出、并发和资源保持原合同。
- 基于事实给状态：代码完成、可编译、论文有加速、本地小算子更快，都不足以单独标记 `validated`。
- 将最终结果写回用户授权的文档与结果入口。不要把内部 prompt、凭据、私有地址或模型权重放入公开研究仓库。

# 性能模型验证：预测变化，而不只是拟合基线

> 状态：验证方案；CPU 数学示例为合成数据。尚无新增 GPU 校准结果。

一个预测器把零改动还原为基线，只能证明归一化成立。真正需要检验的是：**它能否预测未参与拟合的工作点、候选方向及瓶颈迁移？**

## 1. 三个数据集合、四类问题

校准集拟合参数；验证集选择模型形式、阈值和超参数；最终留出集只用于评价。另保留分布外集合观察失效边界。按请求族、长度区间、shape、模型或硬件分组，而不是随意拆分一条强相关 trace。

| 层次 | 要预测的对象 | 必须保留的对照 |
| --- | --- | --- |
| 资源账本 | FLOPs、各层流量、通信与容量 | 算法计数、实际计数器和布局 |
| 算子 | 特定 shape/dtype/backend 耗时 | 形状留出与独立重复 |
| 执行图 | 重叠后完成时间、关键路径 | CPU/GPU/通信时间线、资源争用 |
| 服务与干预 | TTFT/TPOT、容量、候选变化 | 相同 arrival trace、缓存与服务约束 |

每层都要保存输入、参数来源、适用域和预测版本。上层误差不是自动归因于下层；排队、调度、观测边界错误也会导致偏差。

## 2. 最低限度的误差报告

对真实耗时 $T>0$，报告有符号相对误差 $(\widehat T-T)/T$ 和绝对误差。接近零的分项使用绝对单位，避免相对误差失真。分别列 prefill、decode、吞吐容量和服务尾部，不合成一个含糊的“准确率”。

优化器还需要预测差值：

$$
\widehat{\Delta T}=\widehat T_0-\widehat T_1,\qquad
e_\Delta=\widehat{\Delta T}-(T_0-T_1).
$$

例如合成真实值为 100 ms 和 96 ms，预测 102 ms 和 98 ms：两点绝对预测都偏高，但收益预测正确。若预测 100 ms 和 90 ms，基线拟合完美，收益却高估 6 ms。搜索决策应同时看收益符号、候选排序和错误筛除优秀候选的比例。

多资源模型要检查“预测瓶颈”和实际区分性实验是否一致。高带宽占用不能独立作为标签，见 [诊断理论](../../theory/diagnosis/README.md)。

## 3. 区间不是装饰

为未知效率选择保守/中性/乐观参数，得到的是情景范围。只有给出数据、分布假设、拟合规则和留出覆盖检查，才能称为统计预测区间。测量噪声、参数不确定性和模型遗漏分别报告。

对于同一环境下的 baseline/candidate，传播共享参数时保持相关性。若假定独立，会错误扩大或缩小差值不确定性。用重复运行估计噪声时按运行或保留相关性的请求块抽样。

## 4. 先做能否定模型的小实验

| 假设 | 最小检查 | 失败后的修订方向 |
| --- | --- | --- |
| 算子有效速率可局部迁移 | 邻近形状与不同 tile 区域各一个留出点 | 分段模型、形状特征、显式回退 |
| 通信主要由消息大小决定 | 同大小改变拓扑/并发 | 增加路径、启动与竞争项 |
| 融合收益由减少流量解释 | 对比流量与 spill/occupancy | 计入寄存器压力及额外指令 |
| 缓存命中能改善服务 | 固定命中长度分布，改变容量压力 | 恢复/驱逐/排队耦合 |
| 多策略收益可组合 | 基线、A、B、AB 四组 | 条件效应与瓶颈迁移模型 |

参数尚不可辨识时优先增加区分性观测，不继续增加拟合自由度。基线与候选重复测量应交错，所有失败、OOM 和不显著结果保留。

# 正负结果与可迁移经验

> 状态：知识表示与更新设计；尚无自动检索或跨会话学习实现。

## 1. 记住条件、机制和证据

“融合有效”太宽泛，“融合无效”也太宽泛。一条可复用知识应是：在给定 shape、dtype、后端、硬件和负载条件下，某项变换减少了哪种成本，并带来怎样的正确性与性能结果。环境变化后，它至多是下一次诊断的先验。

将原始事实与解释分开保存。事实可以是某次编译错误、计数器或性能数据；解释可以是寄存器压力导致回归。解释后来被推翻时，原始事实仍保留。

## 2. 记录结构

| 字段 | 内容 |
| --- | --- |
| identity | 候选 ID、父版本、patch/config hash |
| context | 模型/引擎/硬件版本、dtype、shape、负载与缓存条件 |
| mechanism | 资源变化、依赖变化、新增开销 |
| prediction | 实验前的收益、不确定性、模型版本 |
| observation | 正确性、性能、成本与原始证据引用 |
| interpretation | 当前解释、替代解释、尚缺证据 |
| status | hypothesis / simulated / measured / validated / inconclusive |
| validity | 已测适用域、外推范围、失效条件、复核触发器 |

索引可先使用 JSONL/CSV 与明确键，不必先搭建向量数据库。语义检索找到相似描述后，还要检查版本和硬约束；文本相似不能证明性能可迁移。

## 3. 负结果分类

| 类别 | 已知事实 | 适合的后续动作 |
| --- | --- | --- |
| unsupported | 当前后端/shape 不支持 | 版本变化后可复核 |
| compile_error | 这一实现未编译通过 | 修复实现，不否定机制 |
| incorrect | 固定 oracle 失败 | 保存反例并隔离候选 |
| no_material_gain | 正确但收益低于门槛 | 检查可消除成本与预算价值 |
| regressed | 正确但正式目标变差 | 分析新增成本与瓶颈迁移 |
| inconclusive | 噪声或证据不足 | 复测、改变诊断粒度或停止 |
| timeout | 分配预算内未完成 | 保留实际消耗，不能推断性能一定差 |

不要把失败都记为零收益后用于回归，因为编译失败的真实运行性能并未观测；这属于缺失/被截断的结果，而非测到了零。

## 4. 更新与迁移

经验复用分三个层级：相同上下文直接参考；相邻 shape/负载作带不确定性的先验；新硬件、后端或模型仅复用机制与实验设计。新结果可以修订解释和适用域，但不覆盖旧结果。

若采用预测残差学习，保存实验前预测和事后结果，按模型/硬件/时间划分留出集。随机拆分高度相似的运行可能泄漏上下文，造成过于乐观的迁移评价。失败记忆也要做消融：它可能减少重复，也可能使 Agent 错误放弃在新环境下已经可行的优化。

## 5. 经验如何进入下一轮决策

输入是当前 context、瓶颈假设和候选机制；输出是相似证据、适用差异和建议的验证，而非自动接受/拒绝。每条建议附原始记录 ID。搜索控制器仍按当前预算与评价契约决策。

最低可检验目标是：使用记忆后，同预算下重复无效实验是否减少，独立确认收益是否改善，错误迁移是否增加。实验设计见 [Agent Benchmark](../../experiments/agent-benchmark/README.md)。这些属于本仓库研究假设，需要真实任务证据。

具体项目可用[复盘指南](../../docs/project-optimization-guide.md)和[项目 Agent 提示词](../../docs/prompts/review-project.md)把这类记录转成下一轮方向；[项目使用子图](../../visualizations/diagrams/research-atlas/06-project.svg)展示结果回写后怎样更新假设与优先级。

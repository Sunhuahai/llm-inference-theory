# Agent 自主优化理论总纲

> 2026-11-25｜状态：`derived / hypothesis`。本文给出本仓库的研究问题与条件分析；没有新增 GPU 实测结果。

## 1. 从“写一个快 Kernel”到“选择值得做的实验”

设当前推理系统有 100 个可改动位置。一次改动可能需要读代码、采集 profile、编译、检查正确性和重复压测。预算有限时，最先遇到的问题是应把时间投入哪个位置、哪个方向、哪种验证。

自主优化系统因此同时需要两种能力：生成可运行改动，以及在不完整信息下选择实验。理论的价值是解释候选的作用机制、潜在收益和失效边界；它仍然可能遗漏实现成本，所以必须接受独立反馈。

本文研究“Agent 优化推理软件”，而非训练 Agent 权重或自动改变目标模型。目标模型、精度、任务分布、质量要求和 GPU 总预算由实验契约固定。

## 2. 统一问题定义

令 $x$ 表示完整实现与配置，$w$ 表示请求负载，$h$ 表示硬件与软件环境，$J(x;w,h)$ 表示预先约定的目标效用，越大越好。可以取负延迟、满足 SLO 的 goodput，或在固定 goodput 下取负资源成本。单位不同的指标不能直接相加；多目标实验先固定约束或报告 Pareto 集。

可行域为

$$
\mathcal F=\{x:q(x)\ge q_{\min},\ M(x)\le M_{\max},\ s(x)=s_0,\ r(x)\le r_{\max}\},
$$

其中 $q$ 为质量标准，$M$ 为峰值状态/工作区容量，$s$ 为模型与任务语义契约，$r$ 为服务所用资源。精确实现的数值容差与随机采样的分布要求应分别约定，不能把“看起来相似”当作正确性。

搜索算法 $\pi$ 产生候选序列 $x_1,x_2,\ldots$，并获得带噪反馈。记 $\mathcal V_t$ 为截至时刻 $t$ 经独立评价、满足契约的候选集合，$x_0$ 为已建立的有效基线。最佳已知候选为

$$
x_t^*\in\arg\max_{x\in\{x_0\}\cup\mathcal V_t}\widehat J_{\rm confirm}(x).
$$

这里的估计来自确认评价；在真实研究中仍须报告不确定性及选择偏差。搜索目标可定义为固定预算内确认效用的期望：

$$
\max_\pi\ \mathbb E[J(x_B^*)-J(x_0)]
\quad\text{s.t.}\quad
\sum_t\mathbf c_t\preceq\mathbf B.
$$

预算是向量，例如 GPU 秒、Agent tokens、墙钟时间与人工分钟。固定相同向量上限最直观；若合并为货币或单个 cost unit，必须公开价格与换算权重。本仓库离线原型仅使用合成 cost unit。

## 3. 状态、动作与反馈

| 对象 | 内容 | 不能混入的内容 |
| --- | --- | --- |
| 可观察状态 | 基线 SHA、负载、profile、已测历史、剩余预算、模型版本 | 尚未评估候选的隐藏结果 |
| 潜在状态 | 真正资源竞争、未观测开销、候选质量与可达性能 | 不应当作已知输入 |
| 动作 | 追加诊断、选择候选、修改代码、选择评价精度、复测或停止 | 静默修改评分规则 |
| 反馈 | 正确性、性能、成本、错误、原始产物引用 | Agent 自报“已加速”不能替代测量 |
| 记忆 | 带作用域的成功、失败和未决判断 | 跨硬件无条件复用的结论 |

这是一个带部分可观测性、延迟反馈和资源约束的序贯决策问题。此表是问题抽象，并不要求必须用强化学习求解。首先使用显式控制器、简单搜索与可解释模型，才能判断更复杂算法是否产生额外收益。

## 4. 自主优化与已有方法的关系

| 方法 | 搜索对象 | 适合作为基线的原因 |
| --- | --- | --- |
| 枚举、随机搜索、贝叶斯优化 | 已定义参数空间 | 成本与搜索条件容易控制 |
| 编译器自动调度 | 合法程序变换、执行计划 | 可以把领域约束编码进空间 |
| Coding Agent | 开放的实现与配置修改 | 能阅读代码、提出新结构 |
| 理论引导 Agent | 开放修改加资源/关键路径/收益模型 | 本仓库待验证的研究方向 |

Ansor 将分层程序表示、进化搜索、代价模型和任务调度结合起来，说明自主优化可借鉴已有自动调度的结构化搜索思想，而不必把所有决策交给语言模型。[1] 约束贝叶斯优化则提供了同时处理目标与未知可行性的研究基础。[2] 二者的公开结果不能直接当作本仓库 Agent 的成绩。

多 Agent 可以并行提出不同机制的假设，也可能重复工作、争抢 GPU 或增加 token 成本。评价应比较职责和信息条件，不能用 Agent 数量代表自主能力。

## 5. 理论如何改变决策

考虑一个**合成例子**：基线关键路径为 100 ms，其中确定可消除的 host gap 至多 4 ms。若候选仅改变此 gap，其他成本与依赖均不变，则候选耗时至少 96 ms，最大延迟下降为 4%，最大加速比为 $100/96$。该条件下声称 20% 延迟下降可被直接否定。

但若该修改也改变 batch、状态驻留或请求排队，原假设失效。此时应该更新模型，而非继续用 4% 作硬上限。理论的作用包括：

1. 用严格成立的约束排除不可行空间。
2. 用可校准预测给候选排序。
3. 在多个瓶颈解释之间选择区分性实验。
4. 根据预测偏差更新模型与不确定性。

一条好假设同时说明“预期为什么变快”和“观察到什么就应放弃当前解释”。

## 6. 从研究问题到可证伪实验

| 假设 | 对照设计 | 支持它需要观察到什么 | 否定或限制它的证据 |
| --- | --- | --- | --- |
| 理论排序提高搜索效率 | 相同候选池和预算，比较随机与理论排序 | 更低达到目标成本，跨任务重复稳定 | 额外分析成本抵消收益 |
| 诊断帮助开放式生成 | 普通 Agent 与诊断增强 Agent，其他工具相同 | 有效候选比例和确认收益提高 | 只增加长解释而无有效改动 |
| 负结果记忆减少重复 | 有/无记忆消融，跨会话任务 | 重复失败减少且外推错误未上升 | 旧负结果错误阻止新机会 |
| 组合模型优于独立叠加 | 单项与联合四组实验 | 组合收益误差降低 | 关键路径迁移导致稳定失配 |

模型构建、profile、检索、编译、失败和复测均计入预算。KernelBench 同时强调生成 Kernel 的功能正确性与速度门槛，可作为局部评价参考；完整推理服务仍需要额外的负载、质量与端到端评价。[3]

## 7. 本模块的当前边界

[离线原型](../systems/README.md) 已实现有限候选选择、预算控制和结果门禁，可检查控制逻辑。真实 Coding Agent、编译环境、GPU profiler 和独立服务评估尚未接入。跨模型、跨硬件泛化与自主优化效率都是待实验检验的问题。

# 自主优化评价：同时测量结果与寻找结果的成本

> 状态：实验设计。随仓库提供的 CPU 回放为 `simulated`；真实 Agent、编译器与 GPU 对照尚待执行。日期：2026-11-25。

核心问题是：**保持模型、任务质量、硬件与搜索预算相同，理论信息能否让优化系统更早找到、更可靠地复现更好的实现？** 一次幸运的最佳 patch 不足以回答这个问题。

## 1. 分开三种优化任务

| Track | 可变动作 | 强基线 | 独立评价 |
| --- | --- | --- | --- |
| 配置选择 | 已存在的 batch、chunk、并行配置与后端 | 有效域内随机搜索、网格/贝叶斯优化 | 固定服务 trace、SLO、资源总量 |
| Kernel 实现 | 一个明确语义算子的实现与调度 | 已有库实现、相同搜索域的 autotuner、普通 Coding Agent | 数值 oracle、多形状与独立微基准 |
| 服务系统 | 引擎内多个模块、缓存/运行时/调度策略 | 固定成熟引擎、普通 Coding Agent | 端到端正确性、负载留出与服务指标 |

配置搜索不能修改代码，因此不能把它和可重写整个引擎的方法直接当成同动作空间的算法对照。可以作为工程参照，同时另做相同动作权限下的搜索消融。[Ansor](https://www.usenix.org/conference/osdi20/presentation/zheng)提供张量程序搜索的参考；[KernelBench](https://arxiv.org/abs/2502.10517v1)把功能正确性和性能阈值结合评价，但它本身不能替代完整服务评价。

初期选一个明确热点和多个形状，完成一条可复现闭环，再增加完整服务任务。任务清单应同时包含成功机会有限、预测容易出错、存在正确性陷阱和优化交互的情况，避免只挑适合理论方法的样例。

## 2. 对照与消融

| 对照 | 可访问的信息/工具 | 能识别的作用 |
| --- | --- | --- |
| A：普通 Agent | 源码、相同 profiler、相同测试、相同工具权限 | 实际自主优化基线 |
| B：A + 理论预测 | 加入资源账本、条件性边界、模型预测 | 显式理论引导的增量 |
| C：B + 成本感知搜索 | 增加预算分配和候选选择 | 搜索组织的增量 |
| D：C + 经验记忆 | 允许读取预先固定的历史库 | 经验迁移的增量 |

主模型版本、Agent 配置与工具权限保持一致。普通 Agent 也可能已经掌握 Roofline 等知识，因此这组实验研究的是“显式理论工具/约束”的作用，而不能证明基线完全没有理论知识。

如果理论组增加了 profiler 信息而基线没有，应再加“同 profiler、无理论模型”对照。历史记忆必须排除测试任务的结果及近重复变体，检索、存储、构建成本也需计费。多 Agent 数量和总 token 数不能同时变化却归因为理论。

## 3. 预算是向量

记累计资源消耗为

$$
\mathbf c_t=(c_{\rm GPU},c_{\rm CPU},c_{\rm LLM},c_{\rm wall},c_{\rm review}),
\qquad \mathbf c_t\le\mathbf B.
$$

分别记录 GPU 秒、CPU/编译时间、LLM 输入/输出 token 和费用、墙钟时间、人工时间。GPU 卡数乘占用时间也不能代替拓扑与卡型信息。并行执行可以缩短墙钟时间，却不自动减少 GPU 总成本。

预算包括基线测量、profiling、模型校准、候选生成、失败编译、超时、回归以及独立复测。公共基线采集可共享，但应在所有方法的账本中采用一致的分摊规则。分别报告首次使用与已有校准库的结果，不能把仅由一种方法承担的准备工作隐去。

用预算上限/超时进行执行前资源预留；成本预测不能当作硬上限。发生超时也必须扣除已耗资源，不能得到“免费失败”。生产控制器的设备租约与终止策略见 [系统设计](../../optimizer/systems/README.md)。

## 4. 什么才算搜索成功

为每个任务事先选定一个主目标，例如最大化满足质量与 SLO 的 goodput，其他指标作为约束。没有明确 SLO 时保留 Pareto 前沿，不自行发明业务阈值。

令 $J_0>0$ 是同条件基线效用，$J^*(c)$ 是消耗预算 $c$ 时**已通过独立接受规则**的最优效用。把基线保留为 incumbent，定义

$$
u(c)=\max\{0,J^*(c)/J_0-1\},\qquad
\mathrm{AUC}_B=\frac1B\int_0^B u(c)\,dc.
$$

对于最小化延迟，先固定 $J=1/T$；不要在同一报告里把延迟下降百分比与吞吐提升百分比混用。该 AUC 是本仓库定义的预算曲线摘要，需要一个事先约定的标量成本轴；其他预算维度仍作为硬限制并单列。若使用加权费用，各项必须统一单位并事先固定权重。

| 指标 | 定义与注意事项 |
| --- | --- |
| 最终效用 | 同预算末端的独立复测结果，同时列完整性能与资源 |
| 达标成本 | 首次达到预注册阈值的累计成本；未达到记为右删失，不删除失败运行 |
| 有效候选率 | 通过正确性且改善可信的候选数 / 全部已尝试候选数（含构建失败与超时） |
| 无效尝试构成 | 编译失败、错误输出、变慢、无显著差异、超时、不可行分别列出 |
| 预测质量 | 符号误差、排序相关、最优候选漏选率、区间覆盖（有校准依据才报告） |
| 泛化 | 未见过的形状、负载、模型/设备上的表现，逐层报告 |
| 复现率 | 独立工作区/环境重建后确认接受的比例 |

**教学算例，非实测：** 总预算 10 单位；方法甲在成本 2 获得 10% 效用提升，在成本 8 达到 20%；方法乙到成本 8 才达到 20%。两者最终成绩相同，按右连续阶梯曲线，甲的 AUC 为 $(6\times0.1+2\times0.2)/10=0.10$，乙为 $0.04$。成本零处没有预先获得的候选收益。基线 goodput 为零时改报绝对改进与可行性，不能计算归一化比值。曲线中的独立接受使用开发阶段的独立复测；最终留出集只在候选与方法冻结后评价，不为画曲线反复查询。

## 5. 独立性、统计与选择偏差

1. 冻结参考实现、正确性阈值、任务定义、测试集和评分脚本。实现 Agent 可以修改目标代码；不能自行放宽误差容限或排除不利样本。
2. 搜索阶段在开发集比较候选。最终候选在未参与选择的留出数据和干净工作区复测；反复查看留出结果会把留出集变成开发集。
3. 性能测量交错 baseline/candidate，匹配缓存、预热、时钟、资源隔离和到达 trace。重 profiler 用于解释，正式性能单独采集。
4. 同一任务对各方法配对运行；改变 Agent 随机种子并保留所有运行。置信区间以独立运行/任务为单位，不能把共享 GPU 上的相关 token 当成独立优化实验。
5. 报告每任务结果与跨任务聚合。若采用加速比几何均值，列出失败和基线保留规则，不能只平均成功任务。

大量搜索后偶然最快的一次测量往往过于乐观。接受流程应重新测量候选，必要时用预先规定的顺序检验或多重比较校正；增加请求数量不能消除软件变更造成的系统性偏差。数值不确定时标为 `inconclusive`。

## 6. 合成回放可以验证什么

运行 [离线搜索控制参考](../../optimizer/systems/README.md)：

```bash
python3 optimizer/systems/replay.py optimizer/systems/examples/synthetic-search.json --policy random --budget 12 --seed 0
python3 optimizer/systems/replay.py optimizer/systems/examples/synthetic-search.json --policy predicted --budget 12 --seed 0
python3 optimizer/systems/replay.py optimizer/systems/examples/synthetic-search.json --policy cost-aware --budget 12 --seed 0
```

候选预测是策略可见的信息；未评估结果由 evaluator 持有。回放验证预算、失败处理和 incumbent 更新，保留预测错误。这里的 `cost_units` 只有合成实验内的意义，不能换算为 GPU 小时；`cost-aware` 不是已经验证的 Agent，也不保证优于随机搜索。模拟实现中的对象隔离不等于真实系统的进程或权限隔离。

## 7. 真实实验的完成条件

至少具备可重建的环境、可执行任务、独立 oracle、原始日志、预算账本、多个独立运行及留出复测，才能讨论真实搜索效果。跨模型/硬件迁移应按 [案例设计](../case-studies/README.md)单独验证。记录使用 [实验模板](../templates/README.md)，方法依据见 [规划与搜索](../../optimizer/planning/README.md)。

本协议借鉴 [KernelBench](https://arxiv.org/abs/2502.10517v1) 的正确性联合性能评价、[Practical Bayesian Optimization](https://arxiv.org/abs/1206.2944v2) 的实验成本视角以及 [Nsight Compute](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html) 的采集扰动说明；分组、预算账本和 AUC 定义为本仓库的研究设计。原始资料核对日期：2026-11-25。
